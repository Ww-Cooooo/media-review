# 把 Media Review 接进 Agent 的出片循环

Agent 需要能在本机执行命令、读取媒体与意见，并能发现或显式加载本 Skill。纯网页聊天平台本身不能运行用户电脑上的程序。将 Skill 文件放进目录并不证明宿主已加载，不能承诺所有宿主强制自动调用。

## 首次接入与核验

安装器输出的“Skill已就绪”后面是实际完整目录。不要凭默认路径猜安装位置；自定义安装目录时，以该回执为准。

在有本机文件／执行权限的 Agent 聊天中，替换下列两个占位符后发送：

> 请读取“<实际Skill目录>/SKILL.md”，把 Media Review 纳入当前剪辑任务：每个可审版本导出完成后主动打开校对室，并在你的制作循环里自检。先在该目录运行 `node scripts/review.mjs doctor` 检查本机环境，再执行 `node scripts/review.mjs after-export --media "<一份已导出成片的绝对路径>"`。回读结果并实际打开返回页面，确认页面中的文件名是这一版；不要只回复“已加载”。

这条显式读取路径不依赖某个宿主的自动发现机制。源码方式则让 Agent 读取本仓库的 `skill/SKILL.md`，从仓库根目录使用 `scripts/review-agent.mjs` 入口。它检验的是本次任务能否接入，不是对所有未来任务强制加载的保证。

核验时应实际看到：命令返回本机网址，浏览器显示这一版媒体且服务运行中；Agent 的 `inspection` 报告明确已完成与未验证项。缺少浏览器工具时不能冒称已查看页面，只能如实报告命令与已生成证据。若命令找不到文件或权限被拒，先补齐路径或权限，不要自行安装全局 hook 来绕过。

## 出片后主动打开

在本 Skill 已进入当前制作任务后，第一版或每个可审返修版写入完成，Agent 就执行入口，不等用户再次说“打开校对室”。

源码项目根目录：

```sh
node scripts/review-agent.mjs after-export --media "<已写入完成的成片绝对路径>"
```

已安装的完整 Skill 目录：

```sh
node scripts/review.mjs after-export --media "<已写入完成的成片绝对路径>"
```

命令实际启动或复用服务、登记这一文件、打开浏览器，并生成独立 Agent 自检资料。网页已有用户草稿时，新版只提示，不自动换片。它不是常驻文件监控，也不在任意剪辑软件导出时拦截事件；没有安装全局 hook。

在自动化或隔离检查中可追加 `--no-browser`，仍启动服务并登记媒体，但不调用系统浏览器。默认真实使用不加这一参数。

成功调用会在标准输出返回 JSON。以下是字段含义，不是某次实际回执：

| 字段 | Agent 应怎样使用 |
| --- | --- |
| `pass` | 入口调用成功；不等于媒体自检或用户认可通过 |
| `url`、`reused` | 打开实际返回的本机网址，区分复用与新启动，不自己猜端口 |
| `media.name`、`media.fingerprint` | 核对实际带入的这版文件；不要只按同名推断身份 |
| `inspection.status` | `limited` 表示缺工具等限制；`needs-check` 表示工具未完成全部检查；`evidence-ready` 只表示相关工具证据已产生 |
| `inspection.reportPath`、`inspection.frameDirectory` | 读取本次真实报告及已生成帧；没有帧就不能假称看过 |
| `inspection.origin`、`inspection.userApproved` | Agent 资料与用户意见分离，不能晋升成用户认可 |

参数／路径／启动失败会以非零退出码和错误消息结束，不能把错误正文当作有效 JSON。保留当前意见，补齐明确缺失的条件后再尝试；不杀未知服务、不覆盖已有成片。仅缺媒体工具时仍可成功打开并手动校对，自检的限制应独立报告。

## Agent 自己也要校对

回读命令输出的网址，使用宿主的浏览器工具打开并确认本轮媒体，检查画面、字幕、声音和节奏。FFmpeg 可提供解码、代表帧及条件黑场／静音证据；缺少工具时返回 `limited`，不会阻断手动校对，也不能说自检已通过。

没有浏览器工具时，可以读取实际 `self-check.json` 和已生成的代表帧，但必须说明只检查了这些资料，不能冒称看过完整动态或听过全片。统计、取帧和程序退出码都不能代替语义、美感或听感判断。

Agent 资料保存在独立 `self-checks/`，带 `origin: agent`、`userApproved: false`，不会混进用户意见。自动打开校对室也不等于用户认可或授权发布。

## 用户实际交接后返修

1. 收到用户粘贴并发送的交接请求后，读取该轮意见和它实际引用的参考图。
2. 根据当前任务核对源媒体。媒体指纹是文件大小加首尾抽样的 SHA-256，不是完整文件摘要；不能仅凭同名文件认定同一片。
3. 按当前被审文件自身时间核对，不能猜它在另一原片中的偏移。参考帧时间与意见区间起点独立，框坐标相对完整视频画幅。
4. “修改”按原话处理，“保留”避免误动，“待讨论”不是批准。有冲突再问必要问题，不擅自改变观点、声音或含义。
5. 输出新的返修成片，不覆盖原媒体、既有成片或旧意见；成功导出后再次调用 `after-export`。

保存、复制、目录中的测试记录或 Agent 自检不自动授权返修。当前任务里已知源媒体时直接核对，不重复索取已知路径；未知时再补齐必要信息。

## 诊断与返修资料包

在已安装 Skill 目录运行：

```sh
node scripts/review.mjs doctor
node scripts/review.mjs self-check --media "<成片绝对路径>"
node scripts/review.mjs export --fingerprint "<当前媒体指纹>" --out "<新的输出目录>"
```

源码目录使用 `scripts/review-agent.mjs` 替换 `scripts/review.mjs`，其余参数相同。

资料包包含可读清单、结构化意见和相对路径参考图，不默认包含原视频、其他轮次、浏览器恢复缓存或绝对源路径；不会自动上传或执行。换电脑时仍需要用户提供原媒体。现有输出目录不会被覆盖。

只有命令行导出才需要指纹。它可在该素材正式意见 JSON 的 `media.fingerprint` 中找到，保存交接弹窗的完整请求也会列出；不要自行按文件名猜指纹。普通用户直接用侧栏“导出返修资料包”，不需要读取这些字段。
