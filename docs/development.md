# 开发与打包

## 从源码运行

需要 Node.js 24+ 与 npm。在仓库根目录执行：

```sh
npm ci --ignore-scripts
npm run build
npm start
```

依赖首次安装需要网络；构建后服务运行不依赖开发服务器或 node_modules 中的服务端库。`npm start` 会打开系统浏览器，服务只监听 `127.0.0.1`，临时端口以当次启动结果为准。构建后根目录的“打开 Media Review.cmd”是 Windows 日常重开入口。

仅需诊断或不打开系统浏览器时：

```sh
node scripts/review-agent.mjs doctor
node scripts/review-agent.mjs open --no-browser
```

本项目保留根目录 `standalone.json` 来选择独立数据根。不要删除该标记后运行，再把框架适配分支的行为当作独立版默认行为。

## 目录关系

- `src/`：React／Ant Design 校对界面；保留 GSAP、Lenis、Fabric 与 AntV G2 的既有职责。
- `server/`：原生 Node 本机服务、认证、记录／参考图、恢复、工具分析、历史与导出。
- `scripts/review-agent.mjs`：源码环境下的主动带入、自检与返修导出入口。
- `skill/`：Skill 说明、安装脚本与启动文件模板，不是可直接安装的完整运行包。
- `public/`：网页标识、桌面IP图标、MiSans 原字体与资产／第三方许可说明。
- `dist/`：前端构建产物，不提交。
- `release/`：完整 Skill 输出目录，不提交；经验证的 ZIP 才作为 Release 附件。

`package.json` 的 `private: true` 只防止意外发布 npm 包，不表示 GitHub 仓库必须私有。

## 测试

```sh
npm test
```

测试也覆盖范围和多框、整片意见、零意见完成、旧记录升级备份、禁止降级丢字段、版本关系、返修进度、用户确认边界、固定交接快照、任务归档、字幕持久化和带编号导出。

测试覆盖原存储／认证／参考图／恢复／交接，以及跨副本十进程冷启动、任务隔离、保存版本校验、编辑租约、旧inbox兼容、空台生命周期、单分析槽、队列容量、上传TTL、取消信号转发、完整内容绑定、可重建结果回收和恢复归档。测试使用隔离目录和合成小样，资源／时钟／工具失败的部分情形是明确的模拟，不需要真实用户意见。

这些 Node 测试不替代浏览器交互、安装器首次安装、真实音视频转写或完整视觉／听感验收。本机通过也不能推导另一台电脑、所有宿主或其他系统均通过。仓库尚未配置或运行远程 CI，不提供虚构的 CI 通过徽章。

需要隔离运行自己的应用检查时，可对测试进程显式设置 `MEDIA_REVIEW_DATA_DIR`，程序在其下再创建 `data/`。只关闭自己创建并确认身份的服务，不杀未知端口或进程。

## 构建完整 Skill

在仓库根目录执行；构建器会将自有源码许可及第三方声明一起带入完整包：

```sh
npm run build:skill -- --out release/media-review-0.3.0-beta.10
```

输出应包含 SKILL.md、README、LICENSE、`skill-package.json`、Windows 启动／安装文件、`scripts/` 和自包含的 `app/`。桌面图标位于`app/dist/brand/media-review-launcher.ico`，多尺寸ICO及品牌说明均登记在清单内；安装和`-InitializeOnly`均为快捷方式设置本安装目录的IconLocation，不引用构建或临时测试目录。包内 `app/` 带构建资源与原生 Node 服务，终端用户不需要 npm 或 node_modules；Agent 通过首次入口准备缺少的 Node.js 24+、PowerShell 7+ 及媒体工具，用户需有受支持的浏览器。

构建器逐项登记文件与 SHA-256；它不证明美感或语义正确，也不执行安装、上传、发布或覆盖旧输出目录。工具／模型、本机绑定、用户媒体、用户意见、恢复缓存和实例身份不进入安装包。唯一随包音频是明确标注为合成语音的 `assets/setup-speech.wav`，用于首次使用的真实字幕自检；自检生成的临时音轨与字幕会清理。

## 安装器与升级

完整包的 `scripts/install.ps1` 支持 `-Destination`、`-DesktopDirectory`、`-InitializeOnly`、`-SkipPageLauncher`、`-ReplacePageLauncher` 和可选媒体工具绑定。页面启动协议默认只注册当前用户、按资料根隔离的固定start动作，不开机自启、不常驻。已有另一安装副本时默认保留，显式Replace也不覆盖未知归属；`scripts/page-launcher.ps1 -Action Unregister`只撤回匹配本副本的登记。隔离验证必须同时指定新的安装位置、桌面位置和数据根；协议测试只注册自身全新根的唯一键，核验归属后清除，不能把默认真实安装当成测试。

相同包可复用；不同版本、未知内容或本机修改会保留并停止，不静默覆盖。旧版本的稳定 Skill ID 和历史数据目录名继续保留；对外显示名不应成为删除或迁移用户数据的理由。

升级前先正式保存并回读，备份私有数据目录及原媒体，不把浏览器未回传草稿当作迁移备份。将新包安装到新目录，按安装器输出的实际新快捷方式打开；旧目标不同的图标不会覆盖，可能另建带后缀的新入口。让宿主只加载你选定的那份 Skill；不熟悉其配置时，用[首次接入核验](agent-workflow.md)中的显式完整路径读取法，不宣称宿主会自动选新版。

打开同一媒体，核对首页正式意见数量、参考图和源文件身份，再决定采用新版。回退时使用保留的旧程序与对应数据备份；不要以旧代码覆盖较新的记录格式。不同端口／安装根的浏览器缓存不保证自动迁移，也不要让新旧窗口同时保存同一素材。

内部保留的历史记录／服务格式前缀用于数据兼容，不代表运行时需要原开发实例。修改这些格式前先设计兼容与恢复，不能为统一名称批量替换。

## 共享服务、容量与保留

这些共享机制自0.3.0-beta.2引入，beta.3／beta.4沿用；旧beta.1包不会自动更新。数据根级启动门闩覆盖检查／spawn／登记，运行门闩由服务整个生命周期持有；Windows使用命名管道，退出由OS释放，不凭PID或陈旧时间抢锁。跨兼容安装副本复用已选定runtimeRoot，核对rootId、dataId、runtimeId、协议和UI版本；不兼容版本明确拒绝。

新任务以UUID落盘，requestId幂等重试。正式意见按任务隔离；同任务保存按加载版本串行比较，覆盖前保留versions。编辑租约使用单调时钟，仅提供交互归属，不能代替提交版本校验。客户端恢复按taskId／clientId捕获上下文，不让晚到的旧任务请求改写新任务。旧资料的共享历史不凭多个inbox登记自动拆分。

| 对象 | 默认预算／动作 |
| --- | --- |
| 任务 | 100项等待、10,000项登记；超限拒绝新增，原文件保留 |
| 重分析 | 全服务1项执行、32项活跃；模型内存估算不够时等待，不杀其他程序 |
| 分析登记 | 最多4,096项；达到后提示整理，不自动删除inspection证据 |
| 上传暂存 | 最多2份，原文件各1GiB、预估总2GiB，闲置120秒回收自身未处理上传 |
| PCM／磁盘 | 解码PCM最多512MiB，上传预检另留256MiB余量；不是所有外部工具的硬磁盘配额 |
| 可重建缓存 | analysis-cache最多128MiB／64文件；jobs中media／browser-upload结果另最多128MiB／64文件，过期标expired |
| 窗口恢复 | 每素材8份热副本，旧副本移入drafts/archive；归档最多1,024份／256MiB，满后拒绝新增而不丢弃 |
| 浏览器恢复 | 每数据根IndexedDB最多1,024份／256MiB逻辑JSON预算，达到时提示保留并整理，不自动删除 |
| 媒体带入 | 最多2个有效窗口授权、总原文件大小预算1GiB；主窗口首次选择，次页默认不下载 |

正式意见、versions、参考图、exports与self-checks不是可重建缓存，不自动按时间删除；保存磁盘满时仍可能失败，必须保留本页输入并处理空间。预算不是对浏览器驻留RAM、冻结标签、外部工具实际模型峰值或任意封装器后代进程的硬保证。显式工具线程参数最多4，不是系统总线程／CPU硬限额。

完整SHA-256与工具／模型文件stamp、参数参与分析缓存，任务在服务实际读取／分析时绑定完整内容。媒体传输核对完整内容后才交出最后一块；源文件缺失／变化不扫描替代品。旧review中的fingerprint仍是抽样身份，不改用户记录格式来冒充完整摘要。

有等待任务、窗口、队列、上传或在途请求时不按旧4小时退出；只有真正空台10分钟宽限。浏览器心跳丢失不据此另开页。退出先取消自己的工具与上传，局部缓存／状态落盘失败不阻止HTTP及运行门闩收尾。lifecycle.json仅记录本服务有限退出状态，不含媒体正文、令牌或完整参数；异常退出只能显示原因未确认。未实测的真实休眠、24小时耐久、跨机或长片峰值不能从模拟测试推出。

### 达到容量后怎样继续

先看具体回执，不把所有满额都当作服务坏了：等待任务满时可明确结束不再等待的任务，32项活跃分析满时可等待或按taskId撤回自己的需求；这两种动作不会减少历史任务／job登记总数。上传闲置与可重建结果按上述预算由服务自身回收，不需删除意见。

4,096项分析登记、10,000项任务总登记、恢复归档或IndexedDB预算满时，当前没有内置的安全批量整理工具。先保留未保存页面，正式保存／回读能保存的输入，并备份整个私有数据根与原媒体；不要为腾容量批量删除task.json、versions、参考图、self-checks或浏览器数据库。确需马上继续新的工作，可明确退出旧根服务后，用新的**绝对路径**`MEDIA_REVIEW_DATA_DIR`启动另一个私有数据根，原根和浏览器资料保留供之后核对。这是隔离继续新任务，不是自动迁移、旧任务已完成或旧草稿已保存；未确认输入仍需保留。旧根的实际归档／整理须逐项核对后进行，不能把达到预算当作删除授权。

## 对外源码边界

只发布本独立源码目录，不在上层工作区执行全量添加。发布前检查私有目录、环境文件、路径绑定、记录、截图与实际媒体；不要只依赖 .gitignore。

GitHub 仓库存可构建源码，完整安装 ZIP 放在 Release 附件。源码上传、Release 发布、安装到真实桌面和用户认可分别记录，不互相代替。第三方代码与字体许可不得被项目自有源码的许可覆盖。
