# 开发与打包

## 从源码运行

需要 Node.js 24+ 与 npm。在仓库根目录执行：

```sh
npm ci --ignore-scripts
npm run build
npm start
```

依赖首次安装需要网络；构建后服务运行不依赖开发服务器或 node_modules 中的服务端库。`npm start` 会打开系统浏览器，服务只监听 `127.0.0.1`，临时端口以当次启动结果为准。构建后根目录的“打开 Media Review.cmd”是 Windows 日常重开入口。

仅需诊断或不打开系统浏览器时：

```sh
node scripts/review-agent.mjs doctor
node scripts/review-agent.mjs open --no-browser
```

本项目保留根目录 `standalone.json` 来选择独立数据根。不要删除该标记后运行，再把框架适配分支的行为当作独立版默认行为。

## 目录关系

- `src/`：React／Ant Design 校对界面；保留 GSAP、Lenis、Fabric 与 AntV G2 的既有职责。
- `server/`：原生 Node 本机服务、认证、记录／参考图、恢复、工具分析、历史与导出。
- `scripts/review-agent.mjs`：源码环境下的主动带入、自检与返修导出入口。
- `skill/`：Skill 说明、安装脚本与启动文件模板，不是可直接安装的完整运行包。
- `public/`：通用图标、MiSans 原字体与第三方许可。
- `dist/`：前端构建产物，不提交。
- `release/`：完整 Skill 输出目录，不提交；经验证的 ZIP 才作为 Release 附件。

`package.json` 的 `private: true` 只防止意外发布 npm 包，不表示 GitHub 仓库必须私有。

## 测试

```sh
npm test
```

测试覆盖记录格式与私有接口、Origin／认证边界、意见交接、参考图、恢复、历史与固定位置打开、波形和进度／取消相关逻辑。测试使用新建临时目录及合成小样，不需要用户真实媒体、模型或意见。

这些 Node 测试不替代浏览器交互、安装器首次安装、真实音视频转写或完整视觉／听感验收。本机通过也不能推导另一台电脑、所有宿主或其他系统均通过。仓库尚未配置或运行远程 CI，不提供虚构的 CI 通过徽章。

需要隔离运行自己的应用检查时，可对测试进程显式设置 `MEDIA_REVIEW_DATA_DIR`，程序在其下再创建 `data/`。只关闭自己创建并确认身份的服务，不杀未知端口或进程。

## 构建完整 Skill

在仓库根目录执行；构建器会将自有源码许可及第三方声明一起带入完整包：

```sh
npm run build:skill -- --out release/media-review-0.3.0-beta.1
```

输出应包含 SKILL.md、README、LICENSE、`skill-package.json`、Windows 启动／安装文件、`scripts/` 和自包含的 `app/`。包内 `app/` 带构建资源与原生 Node 服务，终端用户不需要 npm 或 node_modules，但仍须安装 Node.js 24+、PowerShell 7+ 及浏览器。

构建器逐项登记文件与 SHA-256；它不证明美感或语义正确，也不执行安装、上传、发布或覆盖旧输出目录。工具／模型、本机绑定、媒体、用户意见、恢复缓存和实例身份不进入安装包。

## 安装器与升级

完整包的 `scripts/install.ps1` 支持 `-Destination`、`-DesktopDirectory`、`-InitializeOnly` 和可选媒体工具绑定。隔离验证必须同时指定新的安装位置、桌面位置和数据根，不能把默认真实安装当成测试。

相同包可复用；不同版本、未知内容或本机修改会保留并停止，不静默覆盖。旧版本的稳定 Skill ID 和历史数据目录名继续保留；对外显示名不应成为删除或迁移用户数据的理由。

升级前先正式保存并回读，备份私有数据目录及原媒体，不把浏览器未回传草稿当作迁移备份。将新包安装到新目录，按安装器输出的实际新快捷方式打开；旧目标不同的图标不会覆盖，可能另建带后缀的新入口。让宿主只加载你选定的那份 Skill；不熟悉其配置时，用[首次接入核验](agent-workflow.md)中的显式完整路径读取法，不宣称宿主会自动选新版。

打开同一媒体，核对首页正式意见数量、参考图和源文件身份，再决定采用新版。回退时使用保留的旧程序与对应数据备份；不要以旧代码覆盖较新的记录格式。不同端口／安装根的浏览器缓存不保证自动迁移，也不要让新旧窗口同时保存同一素材。

内部保留的历史记录／服务格式前缀用于数据兼容，不代表运行时需要原开发实例。修改这些格式前先设计兼容与恢复，不能为统一名称批量替换。

## 对外源码边界

只发布本独立源码目录，不在上层工作区执行全量添加。发布前检查私有目录、环境文件、路径绑定、记录、截图与实际媒体；不要只依赖 .gitignore。

GitHub 仓库存可构建源码，完整安装 ZIP 放在 Release 附件。源码上传、Release 发布、安装到真实桌面和用户认可分别记录，不互相代替。第三方代码与字体许可不得被项目自有源码的许可覆盖。
