# Windows 安装与首次校对

本说明对应 **0.3.0-beta.4 Windows预发布完整包**，可从[本版发布页](https://github.com/Ww-Cooooo/media-review/releases/tag/v0.3.0-beta.4)下载完整ZIP及校验文件。本版的安装／初始化入口会为桌面快捷方式配置随包的小电视IP图标，同时保留beta.3的页面重启／本机唤起、分析浮窗定位、任务专属入口和视频放大／全屏；旧安装不会自动升级。源码仓库中的`skill/`只是模板；完整包同时包含`skill-package.json`、`app/`、`scripts/`、SKILL.md、README和安装入口。

## 准备运行环境

- Node.js 24 或更新版本，用于运行本机服务。从 [Node.js 24 官方下载目录](https://nodejs.org/dist/latest-v24.x/)选择 Windows `.msi` 安装版；常见 x64 电脑选文件名以 `-x64.msi` 结尾的包，ARM64 电脑需对应的 `-arm64.msi`，后者未在本项目完成同等验证。安装时保留 npm 组件，供源码构建使用；完整安装包运行不需要 npm。
- PowerShell 7 或更新版本，按[微软官方 Windows 安装说明](https://learn.microsoft.com/zh-cn/powershell/scripting/install/install-powershell-on-windows)使用官方安装包。命令是 `pwsh`，它与 Windows PowerShell 5.1 并存，不能用后者代替。
- Microsoft Edge、Chrome 等支持素材编码的现代浏览器。

在终端检查：

```sh
node --version
pwsh --version
```

找不到命令时先安装对应运行环境并重新打开终端。Media Review 不自动下载运行环境、媒体工具或模型。

## 安装

1. 将完整 ZIP 解压到普通本机目录，不要只取出 SKILL.md。
2. 双击“安装 Media Review.cmd”。默认安装到当前用户的 `.claude/skills/media-review`，创建使用随包小电视IP图标的“Media Review”桌面快捷方式，并注册按资料根隔离的当前用户页面启动协议，说明为“启动 Media Review 本机音视频校对室”。
3. 等待安装器明确报告 Skill 和桌面入口就绪，再双击图标打开。无需管理员权限，不设置开机启动、不改其他 Skill。

如果目标已有不同版本或本机修改，安装器会保留原内容并停止，不自动覆盖升级。先备份并选择新位置，不要删除旧数据来绕过提示。

仅复制完整包到其他宿主 Skill 目录的用户，首次运行“初始化桌面入口.cmd”补建图标。复制本身不会执行脚本或创建快捷方式，宿主是否发现 Skill 仍由宿主决定。

## 保存第一条意见

1. 打开浏览器能播放的视频或音频。
2. 暂停在要修改的位置，点击“标记时间点”，写一条意见。
3. 点击“保存这条意见”。写入并回读确认后，表单进入空白新意见。
4. 回到主页，在“校对任务”找到这一项，点“查看资料”打开该任务的保存目录。

继续已有任务请从任务列表进入；原路径已移动时用“手选同版”，核对文件名、大小、抽样身份及已记录的修改时间。另一个意图需要新建时，点击“手选素材，新建独立任务”，不会沿用旧意见。存在多个同素材任务时要明确选择，不按指纹自动合并。

视频播放条右侧提供“放大”和“全屏”；按Esc或返回按钮退出，保留当前位置、速度与意见。浏览器拒绝系统全屏时，会提示并改用页内放大。多个对话送来的新片进入任务列表，不自动换走当前素材；具体任务用各自的定位链接打开。

整轮完成时点击“保存并交给 Agent”，复制后回聊天实际发送请求，才交给 Agent 返修。没有 Agent 也能使用校对室，导出的返修资料可以交给剪辑人员。

## 可选工具与其他目录

从完整包目录执行，参数中的占位符需换成实际路径；路径中有空格时保留引号。`-Destination` 是**这个 Skill 包自身的完整目标目录**，不是上一级 `skills` 父目录；安装器不会自动再补一层 `media-review`。例如宿主的发现目录是 `<宿主的skills目录>`，目标可填 `<宿主的skills目录>\media-review`：

```powershell
pwsh -NoProfile -File .\scripts\install.ps1 -Destination "<宿主的skills目录>\media-review" -Ffmpeg "<ffmpeg.exe的绝对路径>" -Whisper "<whisper-cli.exe的绝对路径>" -Model "<离线模型的绝对路径>"
```

这些工具是可选的；只需指定已有且要使用的文件，可以省略未准备的参数。绑定只写入本机私有 `tools.json`，不进入分享包；已有绑定不会静默替换。安装器的 `-DesktopDirectory` 只用于明确指定快捷方式目录，例如隔离测试；不需要普通用户设置。

没有分析工具时仍可播放、手动标注、保存与交接。波形和转写会提示不可用，不会假装已分析。

### 分析工具接入范围

- FFmpeg 可从本机 PATH 查找，或用 `-Ffmpeg` 指定。Agent 解码／代表帧自检还要求同一目录中有 `ffprobe.exe`；`doctor` 不单独证明 FFprobe 已就绪，具体结果以自检报告为准。
- 语音入口是 **whisper.cpp 的 `whisper-cli`**，不是任意同名 Whisper 库或云端 API。当前实现使用 `-m`、`-f`、`-osrt`、`-of`、`-pp`、`-ng` 参数，模型应是该 CLI 能加载的 GGML `.bin` 模型；现有流程使用 small 模型，不自动替用户选模型或下载模型。
- 当前转写固定以 `-l zh` 调用，未提供语言选择控件；不要将它理解为任意语种／任意 CLI 版本均已验证。
- 本机检查环境为 Windows x64、Node.js 24、PowerShell 7 与 Edge。其他系统架构、浏览器编码组合和任意媒体工具发行版没有同等验收；Chrome 是建议浏览器，不等于所有 Chrome 版本／编码均测试通过。

工具是否找到、自检是否完成、台词是否准确和用户认可分别判断。不能因工具有文件名就宣布分析通过。

## 服务断开或重开

出现“暂无法连接”时先保留旧页，不要刷新或关闭有未保存输入的页面。页头连接状态右侧会显示“重启服务”；已配置本资料根的Windows页面入口时，点击它或下方断线提示内的“启动 Media Review 本机校对室”，均请求系统唤起安装时固定的Node.js入口；未配置时用桌面或“启动 Media Review 本机音视频校对室.cmd”。服务正常时复用，确已退出时按需启动；只有真实连接与新认证核验通过才显示恢复。原端口被占用时可能另开新地址，旧页需保留，不保证自动跨地址恢复。浏览器可能要求确认；取消或被拦截时不会假报成功。

服务在线时可从“任务操作 → 重启校对服务”核对所有窗口、分析、上传及未保存输入，再明确重启。先准备一次性接续入口，失败时保持旧服务运行；成功准备后才退出旧服务，不刷新或关闭浏览器。未完成分析可能中断，页面恢复后可能重新排队；重启不等于保存完成。“退出整个校对室”仍只退出，不自动重启。

### 启动入口的用途与安全软件提示

入口名和说明为“启动 Media Review 本机音视频校对室”，作用是启动本机Node.js校对服务，不上传素材、不开机自启、不增加常驻启动器。系统可能显示Node.js、node.exe、脚本程序或未知发布者，不能保证名称完全一致或所有安全软件放行。请核对安装来源、实际路径和拦截详情；不要求关闭防护、随意加排除或绕过系统确认。详情见完整包的“启动入口说明.txt”。

安装器仅在`HKCU\Software\Classes`注册当前用户、按资料根隔离的`media-review-<资料根摘要>`协议，网址只能请求固定start动作；不接受任意命令或文件路径。跳过本次注册可加`-SkipPageLauncher`；已有另一Media Review副本的登记默认保留，明确采用新副本时才加`-ReplacePageLauncher`。未知归属不覆盖。自定义资料根要在安装前设置绝对路径`MEDIA_REVIEW_DATA_DIR`，注册命令固定绑定该根，不会因浏览器未继承终端变量而误开默认资料。

取消登记的方法与精确参数见[完整包README的入口说明](../skill/README.md#启动用途安全软件与协议登记)。取消只处理匹配本安装副本的协议和启动配置，不关闭服务、不删除意见；移动或删除安装目录前先取消本入口。仅运行源码或复制SKILL.md不等于注册成功。

有待人工任务／窗口／排队／上传／在途保存时，不按旧30分钟或4小时关闭；只有真正空台默认10分钟宽限后回收。挂起保存已确认恢复副本并卸载本页媒体，任务仍等人；结束任务保留历史、不表示认可；退出整个服务会影响所有窗口与分析，必须明确确认。

Agent登记的原文件可重新带入。手选文件要从对应任务重新选同一版本；未确认的最后输入、清理浏览器缓存、源文件变化或端口冲突不能保证零损失。恢复副本不是正式保存。

默认私有数据在用户主目录的`.media-review-desk/data`，与程序分开。新任务在`tasks/<taskId>/reviews`下分别保存，旧`reviews`与`inbox`保留；恢复旧资料不等于自动拆分过去混用的意见。迁移要备份整个数据根和原媒体，不能仅复制程序。

## 从beta.1／beta.2／beta.3升级

1. 先在旧窗口正式保存并回读，备份私有数据根和原媒体。不要把浏览器中未回传的输入当作已备份。
2. 将新包安装到明确的新位置，不覆盖旧安装；让宿主使用选定的新Skill完整路径。已存在不同快捷方式目标时，安装器保留旧图标，可能创建带后缀的新入口，以回执为准。
3. 不兼容旧版仍运行时，新入口拒绝共写，不会自动杀进程。beta.2先从旧页“任务操作 → 退出整个校对室”明确退出；beta.1没有界面退出按钮，可从新完整包目录先运行以下只核对命令：

   `node scripts/review.mjs quit-legacy --legacy-root "<旧包app目录的绝对路径>"`

   它只检查旧登记、实际目录与已知beta.1服务身份。确认各旧窗口已保存且要退出后，才在同一命令加`--confirm`。令牌只在内存使用，不写网址或日志；身份不符不发送退出，不关闭浏览器、不删除资料。
4. 此命令仅处理session登记的那一个旧服务。beta.1可能存在未登记的重复服务或独立CLI自检，不能声称它们全部退出。无法核实旧副本时，不混跑默认数据根：先用新的**绝对路径**`MEDIA_REVIEW_DATA_DIR`隔离测试，再在旧服务明确停止后采用完整备份迁移，不扫描／结束未知PID。
5. 从新入口选择任务，核对正式意见、参考图与正确原片。旧current登记进入等待，其余旧交接在“包含已结束任务”中选择“继续旧交接”；原文件不改。新Agent送片默认独立任务，不自动采用旧意见。回退时使用保留的旧程序与对应数据备份，不让旧代码写新任务资料。
