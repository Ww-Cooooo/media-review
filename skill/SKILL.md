# Media Review｜本机音视频审片与返修衔接

把音视频校对顺滑接进制作与剪辑流：每当导出可播放成片或返修新版，顺手送进本机 Media Review 校对台并完成技术自检；用户按时间段或画幅框选交回意见后，精准对齐修改并保留已认可段落。

---

## 🎬 1. 准备、送审与返修的实用衔接

1. **首次准备与按需复用（不重复折腾环境）**
   - 首次在本机准备打开校对台或送片前，先简短告知可能需要联网补齐缺失的运行组件/音视频工具与语音模型（全缺约 `0.8 GB`），运行 `<skill-dir>/scripts/first-use.cmd`（紧接送片时加 `--no-browser`）自动检查并复用已有配置，不重复下载。
2. **出片即送审，不抢用户当前窗口**
   - 新成片导出落盘后，调用：
     `scripts/review.cmd after-export --media "<成片绝对路径>" --request-id "<新建UUID>" --label "<简短来源>"`
     （同一作品返修新版时加上 `--previous-task "<上一版taskId>"`，按需加 `--check-times` 抽帧）。
   - 记住返回的 `task.id`、`taskUrl` 与 `inspection.id`，用 `scripts/review.cmd status --task "<taskId>" --job "<jobId>" --result` 查看异步自检结果与抽帧目录，不在后台死循环忙轮询，也不额外乱开浏览器标签页抢占用户正在审的片子；收尾时保持服务在线等待用户审阅，不默认 `quit`。
3. **按用户框选与时间轴意见精准返修**
   - 收到用户交接的意见包后（详见按需参考 [repair-loop.md](references/repair-loop.md)），绑定对应 `taskId` 与意见修订版：修改项逐条落到实处，保留项绝不误伤，“待讨论”项先跟用户对齐；技术解码/抽帧通过与完整动态听审、人工认可如实分开交代，不覆盖原片与历史版本。

## 📊 2. 高可读性沟通规范（拒绝文字墙）

向用户汇报送审入口、技术自检结果或逐条返修进度时，保持清爽一目了然：

- **送审信息与逐条返修优先用紧凑表格**：
  - 例如返修汇报用 **3–4 列短表**（`⏱️ 原时间/框号 | 💬 用户意见 | 🔧 本版实际修改与新时间点 | ✅ 状态`）替代大段流水账，单格短句化。
- **字号、字体与语义图标层次**：用 `## / ###` 小标题分节，用 `` `taskUrl / taskId / 文件名 / 时间码` `` 等宽胶囊方便复制定位，用 `**加粗**` 标出关键变动，配克制图标（`🎬`、`🔗`、`✅`、`⚠️`、`🔧`）；不使用 `<span style>` 等易乱码的原生 HTML 标签。
